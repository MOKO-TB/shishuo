## 三、关键改动点（6 个文件）

### 1. `server/index.mjs` —— gzip 与安全响应头

**改了什么**

```js
import { createGzip, gzipSync } from 'node:zlib'

// 静态资源：只压文本类，且 >1KB；图片/字体已是压缩格式，再压会更差
const COMPRESSIBLE_EXT = new Set(['.html', '.js', '.css', '.json', '.svg', '.map', '.txt'])

// API 响应：包住 res.end，统一压缩 JSON
function attachCompression(req, res) { ... }
```

- 静态大文件走 `createGzip()` 流式压缩，不占内存
- API 的 JSON 由 `res.end` 拦截统一压，无需改动几十处 `sendJson` 调用
- 新增 `Permissions-Policy`；`Strict-Transport-Security` 仅在真的走 HTTPS 时下发（本地 http 下发了会让浏览器把域名永久升级）

**为什么这么做**：原服务端所有响应都是明文未压缩，2MB 首屏对 2.5Mbps 出口意味着 7 秒以上。gzip 是改动最小、收益最大的一步。

---

### 2. `server/api.mjs` —— 三处：响应缓存、SSRF 拦截、预压缩缓存

**（a）`/api/state` 响应缓存**

原实现每次请求都执行 `projectWorkspace(parsedWorkspace(row), user)` —— 解析 154KB JSON、按角色过滤、深拷贝。20 并发时全部挤在 Node 主线程上。

```js
function buildStateResponse(row, user) {
  const key = `${revision}|${user.id}:${courses}:${isAdmin}`
  const hit = stateResponseCache.get(key)
  if (hit && Date.now() - hit.at < 30_000) return hit     // 直接命中
  ...
  const body = JSON.stringify(payload)                    // 序列化也只做一次
  const entry = { body, gzip: null, at: Date.now() }
}
```

**缓存键为什么安全**：`revision` 每次成功写入都递增，数据变了 key 就变了；账号的课程分配或管理员身份变化也会改变 key。

**（b）gzip 结果也缓存**

第一版只缓存了投影对象，实测并发反而变慢（p50 106→136ms）——因为每次仍要 `JSON.stringify(154KB)` + `gzipSync(154KB)`，压缩是 CPU 密集操作，20 并发直接把主线程压满。

改为连压缩结果一起缓存，热路径只剩「读 Buffer + 写 socket」：

```js
if (!entry.gzip) entry.gzip = gzipSync(Buffer.from(entry.body, 'utf8'), { level: 6 })
res.setHeader('Content-Encoding', 'gzip')
return res.end(entry.gzip)
```

**（c）AI Base URL 的 SSRF 拦截**

```js
function isPrivateHost(hostname) {
  // 127/8、10/8、172.16-31、192.168/16、169.254/16（云元数据）、100.64/10、::1、fc00::/7
}
```

原代码只校验了「协议必须是 http/https、长度 ≤500」，因此 `http://169.254.169.254/latest/meta-data/` 能通过 —— 管理员会话一旦被劫持，就能让服务端把 API Key 发到内网或读走云实例凭证。

保留 `AI_ALLOW_PRIVATE_BASE_URL=1` 开关，方便本地联调 mock 上游。

### 3. `server/permissions.mjs` —— 同学提问一律脱敏

**改动**

```js
// 原：只对 anonymous===true 的 thread 脱敏
.map((thread) =>
  thread.student?.id === user.id || !isAnonymousThread(thread) ? thread : redactThread(thread))

// 改：只要不是自己的，一律脱敏
.map((thread) => (thread.student?.id === user.id ? thread : redactThread(thread)))
```

`redactThread` 额外剔除 `escalation.note`（学生写给老师的私密补充，如「作业最后一题要用」）。

**为什么**：前端 `StudentView.tsx` 的 `useState(false)` 让提问默认实名，而 `studentCourseTeacherMap` 又给每个学生开放全部试点课程 —— 两者叠加，任意学生登录即可看到同学的实名、原题、作业紧迫度。改后实测 7 条他人问答全部显示「匿名同学」，真实姓名 0 条。

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 原始响应体 | 154,361 B | 153,943 B（少了 `escalation.note`） |

**关于并发提升幅度**：本地是环回网络，带宽不是瓶颈，所以 gzip 带来的传输收益体现不出来，反而在「每请求都压缩」时拖慢了（第一次实测 p50 从 106ms 升到 136ms）。把压缩结果也缓存后回到 99ms。

**线上（2.5 Mbps 出口）的收益会远大于本地**：20 并发 × 154KB ≈ 3MB 需要约 9.8 秒传输，压到 49KB 后约 3.1 秒；且服务端不再重复做投影与序列化。

**响应体构成（优化后 160,810 B 拆解）**：

| 字段 | 大小 | 占比 |
|---|---|---|
| **faqs** | **150,371 B** | **93%** |
| threads | 9,230 B | 5% |
| notifications | 624 B | 0% |
| 其余 | ~600 B | 0% |

单条 FAQ 平均 976 B（含 `aliases` / `answer` / `citations` 等 14 个字段），154 条。

**这印证了报告的判断**：`/api/state` 的大头是 FAQ，不是问答本身。下一步要真正把 154KB 降到 15KB 量级，必须拆 `/api/faqs?courseId&page` 并让前端按需加载 —— 但那会改动 `src/lib/engine.ts` 的本地检索逻辑，属于架构改造，本次未做。

## 五、必须说明的三处结论修正

复核源码 + 本地实测后，之前报告里有 **3 条判断不成立**。这里逐条更正，避免团队按错误结论整改。

### 1. 「学生可 `PUT /api/state` 越权全量覆盖」—— 不成立

`server/permissions.mjs:285` 的 `mergeStudentThread` 用 `assertOnlyChanged(prev, next, STUDENT_THREAD_FIELDS)` 做字段白名单，学生只能改 `feedback / resolvedAt / withdrawnAt / favorite / escalation / clusterId / status / studentSupplement`，改不动他人问答正文、引用与老师回复。

**当时的推理错在哪**：`api.mjs:1803` 的 revision 比对发生在 `authorizeAndMerge` **之前**，任何已登录用户带着过期 revision 都会拿到 409，与写权限无关。**不能用错误码反推权限，要先确认这个错误码产生在权限检查之前还是之后。**

**连带影响**：原报告排期第 3 项「`PUT /api/state` 加角色校验」已删除 —— 学生的提问、转问、反馈、收藏全走这条整包同步，加了 `requireRole` 会让**学生无法提问**。

### 2. 「登录无限流」—— 不成立

`server/api.mjs:408-426` 已有实现：同一 `IP:email` 连续 8 次失败 → 封禁 15 分钟。实测第 9 次返回 429。

**当时为什么漏判**：黑盒只测了 6 次错误密码，没到阈值。

### 3. 「键盘焦点完全不可见」—— 不成立

`src/styles/base.css:275` 已有全局 `:focus-visible`。实测按 Tab 键，焦点按钮的计算样式是 `outline-style: solid; outline-width: 2px; outline-color: rgb(20,108,86)`。

**当时为什么漏判**：用 JS `element.focus()` 触发聚焦，**不会匹配 `:focus-visible`**（浏览器只在键盘交互时匹配）。测可访问性必须用真实的 Tab 键。
