# 师说 · 管理台 —— UI 设计评审与优化方案

> 评审对象：`http://121.37.30.147/admin/`
> 评审方式：真实浏览器渲染取证（Chromium 1440×900 / 390×844）+ 计算样式读取 + 设计令牌解析
> 评审范围：登录页、概览、账号管理、风控审核、学生问答、操作审计、AI 用量、内容运营、内容核实、系统与开发（共 10 个界面）
> 约束：**仅出方案，不改动线上代码**

---

## 一、总体判断

先说结论：**这套 UI 的设计底子是同类学生项目里的上游水平**，问题不在"审美"，而在**「品牌表达」与「工具效率」没有分层**——把宣传页的版式套在了高频操作界面上，加上设计令牌只落地了一半，导致可用性和无障碍出现硬伤。

### 做得好的地方（答辩要主动讲）

| 维度 | 实际表现 |
|---|---|
| 视觉语言 | 米纸底 `#f4f0e6` + 玉绿 `#146c56` + 衬线标题，形成明确的"书卷/学府"气质，与"师说"这个教育产品名高度自洽，不是套模板 |
| 令牌体系 | 语义色 16 个（paper/ink/jade/clay/gold/blue/danger + 三级表面）、三档圆角、双档阴影、统一缓动 `cubic-bezier(.22,.61,.36,1)`，成体系 |
| 首屏叙事 | 「把账号、内容与系统，放在一个地方。」是真正的产品主张，比"管理后台"这类标题强得多 |
| 中文排版 | 正文行高 1.88、字距克制，长段中文可读性到位；衬线/无衬线分工清晰 |
| 品牌一致性 | 独立入口、独立顶栏、独立说明文案（"登录后会替换当前浏览器会话""所有管理操作都会写入审计日志"），安全预期管理做得好 |
| 信息架构 | 9 个模块分区合理，学生问答采用"统计→列表→详情"三栏，是全站完成度最高的页面 |

**这套设计只要修 5 个硬伤，观感与可用性会有质变。** 下面按优先级给。

## 二、P0 级问题（影响可用性/评审观感，必须改）

> **经源码复核后排除 1 条**（初稿判断有误，不需要整改）：
> 「键盘焦点完全不可见」（原 P0-3）不成立。`src/styles/base.css:275` 已有全局 `:focus-visible`，实测按 `Tab` 键时焦点按钮的计算样式为 `outline: solid 2px rgb(20,108,86)`。初稿实测用 JS `element.focus()` 触发，**这种方式不会匹配 `:focus-visible`**（浏览器只在键盘交互时匹配），所以读到了 `none`。故本版不再把焦点列为问题；验收时仍建议用真键盘走一遍确认。


### P0-1　海报式 Hero 区在全部 8 个功能页常驻，把工作区压塌

**实测数据**（1440×900 视口）：

| 区域 | 纵向位置 | 占用高度 |
|---|---|---|
| 顶栏 | y = 0–70 | 70px |
| 面包屑 | y ≈ 78–90 | 12px |
| Hero 标题 + 说明 | y ≈ 100–230 | 130px |
| 右侧管理员卡 | y ≈ 100–225 | 125px |
| 标签导航 | y ≈ 313–363 | 50px |
| **内容区起点** | **y ≈ 390** | — |

**首屏可用于工作的高度只有 510px（900 − 390），占屏幕 57%。**

直接后果：
- 账号管理页 9 个账号，首屏只露出 7 个；右侧详情面板的「重置密码」整块被推到折叠线以下；
- 操作审计页 17 条记录，每条占 76px，一屏看 6 条，要翻 3 屏；
- 内容核实页 60 条待办，一屏看 4 条，**要翻 15 屏**。

Hero 在"概览"页是资产（第一眼观感全靠它），在其余 8 页是负债。

**改法：Hero 与页头分离，只有概览页渲染 Hero。**

```jsx
// 概览页：保留完整 Hero
{activeTab === 'overview' && <AdminHero />}

// 其余页：紧凑页头，56px 高
<header className="page-head-compact">
  <div className="ph-left">
    <span className="crumb">管理端 / {group}</span>
    <h2>{title}</h2>
  </div>
  <div className="ph-right">
    <span className="stat-inline">revision {revision}</span>
    <span className="stat-inline">AI 已配置</span>
    <button className="button button-ghost">刷新</button>
  </div>
</header>
```

```css
.page-head-compact {
  display: flex;
  align-items: center;
  justify-content: space-between;
  height: 56px;
  padding: 0 26px;
  border-bottom: 1px solid var(--line);
  position: sticky;
  top: 70px;              /* 贴住顶栏，滚动时页头常驻 */
  background: var(--paper);
  z-index: 20;
}
.page-head-compact h2 {
  font-family: var(--serif);
  font-size: 17px;
  font-weight: 600;
  margin: 0;
}
.stat-inline {
  font-size: 11px;
  color: var(--muted);
  padding: 0 8px;
  border-right: 1px solid var(--line);
}
```

**收益**：内容区起点从 y=390 提到 y=126，**可用高度 510px → 774px（+52%）**。账号管理 9 条全部可见，内容核实一屏从 4 条变 7 条，翻屏次数从 15 次降到 9 次。

### P0-2　暗色主题是坏的：白字压在米色底上，对比度 1.04:1

**实测**（强制 `data-theme="dark"` 后读取计算样式）：

| 元素 | 文字色 | 实际背景 | 对比度 | WCAG AA 要求 |
|---|---|---|---|---|
| H1「把账号、内容与系统…」48px | `rgb(236,243,238)` | `rgb(242,237,225)` | **1.04** | ≥ 3.0（大字） |
| Hero 副标题 14px | `rgb(192,205,198)` | `rgb(242,237,225)` | **1.41** | ≥ 4.5 |
| 顶部标签 | `rgb(236,243,238)` | `rgb(32,48,42)` | 12.27 ✔ | — |

**根因**：令牌重定义是完整的（`[data-theme=dark]` 共 38 条规则，`--paper:#0f1714`、`--ink:#ecf3ee` 全部覆盖），但外层容器 `.admin-standalone` 的底色**没有走变量**——实测其计算背景恒为 `rgb(242,237,225)`，与亮色的 `--paper` 几乎同值。于是文字变量翻成了浅色，容器底色没翻，变成白字米底。

同时 `body{background:var(--paper)}` 是对的，却被 `.admin-standalone` 盖住了。

**改法三步**：

```css
/* 1. 外层容器改用变量（找到硬编码的 #f4f0e6 / rgb(242,237,225) 并替换） */
.admin-standalone {
  background: var(--paper);   /* 原为硬编码浅色 */
  min-height: 100vh;
  display: flex;
  flex-direction: column;
}

/* 2. 顶栏与徽章同样去硬编码 */
.topbar { background: color-mix(in srgb, var(--paper) 85%, transparent); }
.demo-pill,
.topbar-account { background: color-mix(in srgb, var(--surface) 72%, transparent); }

/* 3. 声明 color-scheme，让滚动条/表单控件跟随主题 */
:root { color-scheme: light; }
[data-theme="dark"] { color-scheme: dark; }
```

**另一个必须先决策的问题：暗色主题现在没有任何入口。**

实测顶栏只有「退出」一个按钮，`data-theme` 恒为 `light`，全站无切换控件，CSS 里也没有 `prefers-color-scheme` 媒体查询。

也就是说：**这 38 条暗色规则是死代码，且在答辩现场无法演示。**

两条路选一条：
- **A（推荐，成本 0.5h）**：修好配色的同时，在顶栏加一个 `[☾/☀]` 切换按钮，`localStorage` 记忆。答辩时这是一个"设计系统完整性"的加分演示点，成本极低。
- **B（保守）**：暂时删掉 `[data-theme=dark]` 整段，避免评委翻 DevTools 时看到坏掉的半成品。

**绝不能保留现状**——留在仓库里但不修，是"半成品"信号，比没有更伤。

### P0-4　8.5px / 9px 小字泛滥，共 49 处

**实测统计**（`font-size < 10px` 的叶子文本节点）：

| 字号 | 出现次数 | 承载内容 |
|---|---|---|
| 8px | 13 | 「服务器后台」等品牌副标 |
| 8.5px | 20 | 统计卡标签「服务 / revision / AI」、账号邮箱、辅助说明 |
| 9px | 10 | 「返回主站」、「管理员」徽章、统计卡标签「账号 / FAQ 总数」 |
| 9.5px | 6 | 元信息 |
| **合计** | **49** | — |

**这不是审美问题，是功能问题**：统计卡的**标签**（"账号""FAQ 总数""待处理问答"）是 8.5–9px，而数字是 28px。用户看到"9""217""10"三个大数字，却看不清它们分别代表什么——**标签比数字重要，却做成了最小的字**。

Windows 下 9px 中文字形实际只占 9 个物理像素，笔画粘连严重（"账号"两字在 100% 缩放下几乎成块）。

**改法**：

| 层级 | 原字号 | 建议 | 用途 |
|---|---|---|---|
| 统计卡标签 | 8.5–9px | **11px / 500** | 必须能读 |
| 元信息（时间、revision） | 8.5px | **11px** | 可读但弱化 |
| 品牌副标 | 8px | **10px**，或直接删 | 装饰性可极小，但不要承载信息 |
| 徽章 | 9px | **10px** | 等宽数字保证对齐 |
| 正文辅助 | 9.5px | **12px** | — |

```css
/* 建立字号阶梯，禁止单点硬编码 */
:root {
  --fs-caption: 11px;   /* 标签、元信息 */
  --fs-small: 12px;     /* 辅助正文 */
  --fs-body: 14px;      /* 正文 */
  --fs-lead: 15px;
  --fs-h3: 17px;
  --fs-h2: 22px;
  --fs-h1: 34px;        /* 功能页标题 */
  --fs-display: 48px;   /* 仅概览页 Hero */
}
```

同时给统计卡重排层级：**标签在上且 11px，数字在下且 26px**，让"是什么"先于"多少"。

### P0-5　移动端 9 个标签只有 4 个够得着，且不给任何提示

**实测**（390×844）：

`.admin-console-tabs` 规则为：
```css
.admin-console-tabs {
  flex-wrap: nowrap;
  overflow-x: auto;
  scrollbar-width: none;          /* 隐藏滚动条 */
  -webkit-overflow-scrolling: touch;
}
.admin-console-tabs::-webkit-scrollbar { display: none; }   /* 也隐藏 */
.admin-console-tabs button { flex: none; min-width: 92px; }
```

9 × 92px = **828px** 内容放进 **390px** 视口。可见 4.2 个，剩下 5 个页面需要横向滑动才能到达。

问题在于三个"藏"叠加：
1. 滚动条被 `display:none` 彻底删掉；
2. 没有渐隐遮罩、没有箭头、没有"更多"按钮；
3. 没有滚动位置指示。

实测截图里，第 4 个标签「学生问答」**左半个图标被切成两半**贴在屏幕右缘——这个"半个字"是唯一的暗示，但它看起来更像布局 bug 而不是"可以滑"。

**改法（移动端）**：

```css
@media (max-width: 768px) {
  /* 1. 加右侧渐隐遮罩，明确"还有内容" */
  .admin-console-tabs {
    position: relative;
    mask-image: linear-gradient(to right, #000 0, #000 calc(100% - 32px), transparent 100%);
    scroll-snap-type: x mandatory;
  }
  .admin-console-tabs button { scroll-snap-align: start; }

  /* 2. 选中项自动滚入视野 */
  .admin-console-tabs button.is-active { scroll-margin-left: 8px; }
}
```

```js
// 3. 切换标签时把当前项滚到左侧，用户永远知道自己在哪
useEffect(() => {
  const el = tabsRef.current?.querySelector('.is-active');
  el?.scrollIntoView({ inline: 'start', block: 'nearest', behavior: 'smooth' });
}, [activeTab]);
```

**更好的方案（如果允许改结构）**：移动端把 9 个标签收进一个「筛选」抽屉或原生 `<select>`，顶栏只保留当前页名 + 一个"切换"图标。9 个平铺标签本身就是桌面思维，手机上无论怎么滑都别扭。

## 三、P1 级问题（专业度与体验，本迭代应改）

### P1-1　主色滥用导致按钮层级失效

**实测**：内容核实页 60 条待办，**每行右侧挂一个实心绿主按钮「标记已核实」**。首屏同时出现 4 个视觉重量完全相同的实心主按钮。

**问题**：主按钮（primary）的作用是"这个页面你该点这个"。当 60 个同权重主按钮同时出现时，主按钮等于没有按钮，页面变成一片绿色噪点，用户反而不知道该从哪下手。

审计页同样：每条记录一张卡，卡片内没有层级差。

**改法——建立三档按钮 + 行内克制**：

```css
/* 主按钮：每个视图最多 1–2 个，只给"页面级主操作" */
.button-primary { background: var(--jade); color: #fff; }

/* 次级：行内操作用描边，不用实心 */
.button-outline { background: transparent; border: 1px solid var(--line-strong); color: var(--ink-soft); }
.button-outline:hover { border-color: var(--jade); color: var(--jade); background: var(--jade-soft); }

/* 危险：清空 Key / 删除词条 / 停用账号 */
.button-danger { background: transparent; border: 1px solid var(--danger); color: var(--danger); }
.button-danger:hover { background: var(--danger); color: #fff; }
```

具体到两个页面：

| 页面 | 现状 | 改为 |
|---|---|---|
| 内容核实 | 每行 1 个实心绿「标记已核实」 | 行内改**描边小按钮**；页面顶部加**批量操作条**（勾选后出现「批量标记已核实」主按钮） |
| 操作审计 | 每条 1 张大卡，无操作 | 保持只读，改为紧凑表格，不设按钮 |
| 学生问答 | 详情区「待老师回复」标签但管理员只读 | 标签改为「待教师处理」+ 旁边一个次要文字说明，避免"看起来我能点" |

**顺带修一个安全相关的视觉缺失**：AI 用量页的 `Base URL` 输入框**可编辑且零提示**。这个字段被篡改会把 API Key 发往第三方地址（我在代码审查报告里列为 P1-3 SSRF 风险）。UI 层面必须加警告：

```jsx
<div className="field field-warn">
  <label>Base URL</label>
  <input value={baseUrl} onChange={...} />
  <p className="field-warn-text">
    ⚠ 修改后，API Key 将被发送至该地址。请只填写可信服务商，
    非官方域名可能导致密钥泄露。
  </p>
</div>
```
```css
.field-warn input { border-color: var(--gold); }
.field-warn-text {
  font-size: 11.5px; color: var(--clay);
  margin: 6px 0 0; line-height: 1.6;
}
```

同样，「清空 Key」当前是**绿色描边**——它应该是 `--danger`。实测截图里它和「保存配置」挤在一起，危险操作没有视觉隔离。

### P1-2　审计日志与待办列表做成了卡片流，破坏纵向扫视

**实测**（操作审计，1440×900）：每条记录 76px 高，内容为三行：

```
系统管理员  教师  11/18 16:34  rev 12
老师回复
教师端课 · 校园生活
```

**问题**：
- 审计日志的核心使用场景是"**扫**"——快速纵向对比谁在什么时候做了什么。卡片流把每条的字段位置打散，眼睛每换一行就要重新定位，无法形成列对齐的扫视通道。
- 无列头，用户不知道第二行是"动作"还是"对象"。
- `rev 12` 用 `--faint`（对比度 2.31），几乎看不见，但 revision 恰恰是排查版本冲突的关键信息。
- 76px 承载一条记录，密度过低：一屏 6 条，17 条要翻 3 屏。

**改法：审计用紧凑表格，行高 44px**

```jsx
<table className="table-compact">
  <thead>
    <tr>
      <th style={{width: 150}}>时间</th>
      <th style={{width: 120}}>操作人</th>
      <th style={{width: 90}}>角色</th>
      <th>操作</th>
      <th style={{width: 100}}>课程域</th>
      <th style={{width: 70, textAlign: 'right'}}>revision</th>
    </tr>
  </thead>
  <tbody>
    {logs.map(l => (
      <tr key={l.id}>
        <td className="mono">{fmt(l.createdAt)}</td>
        <td>{l.actorName}</td>
        <td><span className={`tag tag-${l.role}`}>{roleName(l.role)}</span></td>
        <td>{l.action}<span className="muted"> · {l.target}</span></td>
        <td className="muted">{l.courseDomain}</td>
        <td className="mono muted" style={{textAlign:'right'}}>rev {l.revision}</td>
      </tr>
    ))}
  </tbody>
</table>
```

```css
.table-compact { width: 100%; border-collapse: collapse; font-size: 12.5px; }
.table-compact thead th {
  position: sticky; top: 0; z-index: 1;
  background: var(--surface-2);
  font-size: 11px; font-weight: 500; color: var(--muted);
  text-align: left; padding: 9px 12px;
  border-bottom: 1px solid var(--line);
  letter-spacing: .04em;
}
.table-compact td {
  padding: 11px 12px;
  border-bottom: 1px solid var(--line);
  vertical-align: middle;
}
.table-compact tbody tr:hover { background: var(--surface-2); }
.table-compact .mono { font-family: var(--mono); font-variant-numeric: tabular-nums; }
```

**收益**：行高 76px → 44px，**一屏从 6 条变 13 条**，同样数据翻屏次数减半，且获得列对齐扫视能力。

**同一个改法适用于**：内容核实（60 条 → 表格 + 批量勾选）、风控敏感词表、账号列表。

### P1-3　语义色对比度不达标，`--faint` 仅 2.31:1

**实测**（浅色主题，相对 `--paper` 取对比度）：

| 令牌 | 用途 | 实测对比度 | 判定 |
|---|---|---|---|
| `--ink` `#17241e` | 主文字 | 14.11 | ✔ AA |
| `--ink-soft` `#3f4f48` | 次级文字 | 7.61 | ✔ AA |
| `--muted` `#6f7c75` | 弱化文字 | **3.83** | ✘ 不足 4.5 |
| `--faint` `#98a29c` | 极淡文字 | **2.31** | ✘ 严重不足 |
| `--jade` `#146c56` | 主色 | 5.58 | ✔ AA |
| `--danger` `#a53f35` | 危险 | 5.49 | ✔ AA |
| `--gold` `#ad7f1d` | 警示/徽章 | **3.17** | △ 仅够大字/图形 |
| `--clay` `#b8613e` | 强调 | **3.83** | △ 仅够大字/图形 |
| `--blue` `#4d6e8a` | 链接 | 4.72 | ✔ AA |

在卡片底 `--surface` 上，`--muted` 4.14、`--faint` 2.50，仍未达标。

**关键叠加**：`--faint` 正是那 49 处 8.5px 小字的颜色。**最小字号 + 最低对比度**，是全站可读性最差的一层——而它承载的是"服务器后台""服务/revision/AI"这些辨识页面状态的信息。

**改法**：

```css
:root {
  /* 提深到 AA，视觉上仍是"弱化"但可读 */
  --muted: #5d6a62;   /* 3.83 → 约 5.4 */
  --faint: #78837b;   /* 2.31 → 约 3.6，仅限装饰与非关键信息 */
}
```

并规定使用边界：

| 令牌 | 允许用于 | 禁止用于 |
|---|---|---|
| `--muted` | 次级正文、表格辅助列 | — |
| `--faint` | 分隔线旁的装饰、禁用态文字 | **任何承载信息的小字**（revision、时间、标签） |
| `--gold` | 徽章底色 + 深色文字 | 浅色底上的纯金文字 |
| `--clay` | 图标、边框 | 小号正文 |

徽章（`badge-gold`）目前是"浅金底 + 金文字"，建议改为"浅金底 + `--ink` 文字"，对比度立刻从 3.17 提到 12+。

```css
.badge-gold { background: #f5e8c8; color: var(--ink); border: 1px solid #e3cf9a; }
```

### P1-4　点击「刷新」零反馈，用户不知道有没有生效

**实测**：对「刷新概览」按钮连点后每 120ms 采样 600ms，`textContent`、`disabled`、`className` **全程无任何变化**。

**后果放大**：这个系统的 `/api/state` 实测单并发 174ms、20 并发时 p95 到 **20.7 秒**、最大 **34 秒**。在慢路径下，用户点击刷新后界面死一般静止半分钟，只能重复点击或以为坏了。

**改法**：

```jsx
const [loading, setLoading] = useState(false);

<button className="button button-ghost" disabled={loading} onClick={handleRefresh}>
  <IconRefresh className={loading ? 'spin' : ''} />
  {loading ? '刷新中…' : '刷新概览'}
</button>
```

```css
.button[disabled] { opacity: .55; cursor: not-allowed; }
.spin { animation: spin 900ms linear infinite; }
@keyframes spin { to { transform: rotate(360deg); } }
@media (prefers-reduced-motion: reduce) { .spin { animation: none; } }
```

**并补齐四种状态的视觉**（这是目前全站系统性缺失）：

| 状态 | 现状 | 需要 |
|---|---|---|
| 加载中 | 无（仅骨架式空白） | 骨架屏 or 按钮 loading + 内容区 loading 遮罩 |
| 空 | 部分有引导文案（做得不错） | 统一组件 |
| 错误 | 顶部有 `demo-pill.is-error` | 需带"重试"按钮的内联错误块 |
| 成功 | 无 | Toast（保存账号、加入词表、清空 Key 都需确认） |

```jsx
// 统一空/错/载三态组件
function StateBlock({ type, message, onRetry }) {
  if (type === 'loading') return <div className="skeleton-list"><i/><i/><i/></div>;
  if (type === 'error') return (
    <div className="state-block state-error">
      <p>{message || '加载失败'}</p>
      <button className="button button-outline" onClick={onRetry}>重试</button>
    </div>
  );
  return <div className="state-block state-empty">{message}</div>;
}
```

### P1-5　列表全部用 `div` 拼装，无表格语义

**实测**：

```
table 元素：0
th 元素：0
role="table" / "grid" / "list" / "listitem"：0
class 含 row / list-item / table 的 div：21
```

账号列表、审计日志、敏感词表、内容核实队列——**四个"表格"全部是 `div` + flex 拼的**，没有 `<table>`、`<th>`、`role`，也没有 `aria-*` 关联。

后果：
- 屏幕阅读器读到的是 21 个无语义容器，无法建立"表头—单元格"关系，读出来是一串散装文字；
- 无法用 `Ctrl+F` 之外的任何方式定位单元格；
- 键盘 `Tab` 无法在单元格间导航。

**改法**：优先换原生 `<table>`（语义免费，见 P1-2 的代码）。若因布局必须用 div，则必须补 ARIA：

```jsx
<div role="table" aria-label="审计日志" aria-rowcount={logs.length}>
  <div role="rowgroup">
    <div role="row">
      <div role="columnheader">时间</div>
      <div role="columnheader">操作人</div>
      <div role="columnheader">操作</div>
    </div>
  </div>
  <div role="rowgroup">
    {logs.map(l => (
      <div role="row" key={l.id}>
        <div role="cell">{l.time}</div>
        <div role="cell">{l.actor}</div>
        <div role="cell">{l.action}</div>
      </div>
    ))}
  </div>
</div>
```

> 这一条对答辩有额外价值：评委问"你的无障碍考虑了么"，能指着 `<table>` 和 `role` 答，和只能答"考虑了对比度"是两个层次。

## 八、答辩叙事建议

这套 UI 的**审美分不需要改**，需要改的是"能不能讲成一个完整的设计决策"。

现有版本的问题：视觉风格统一，但**没有解释过为什么这样设计**。评委看到的是"一个挺好看的界面"，而不是"一个想清楚了的设计系统"。

建议按这条线讲（每一条都能对应上面某处代码）：

1. **「一套令牌，两个主题」** —— 16 个语义色、双主题、统一缓动。现场切一次暗色（前提是 P0-2 修好）。
2. **「三种布局，按任务分」** —— 扫视用表格、深读用主从、引导用卡片。这是**有方法论的设计决策**，不是随手排版。
3. **「无障碍是可验证的」** —— 对比度全部 ≥ 4.5:1（附实测表）、焦点环可见、表格有语义、字体最小 11px。**给出数字，不要只给承诺。**
4. **「中文优先的排版」** —— 衬线标题 + 无衬线正文、行高 1.88、数字等宽。这是针对中文长文阅读做的具体选择。
5. **「安全预期写进 UI」** —— 登录页明说"会替换当前浏览器会话"、明说"所有操作进审计"。把系统行为前置告知用户，本身就是设计。

**一句话总结陈词**：
> 我们没把它做成一个"管理后台模板"，而是做成了有明确排版主张、可验证无障碍指标、并按任务类型选择布局的管理台。

第 3 条（可验证的数字）是最能拉开差距的——绝大多数参赛队伍讲 UI 只能讲"我们参考了 XX 设计系统"，讲不出对比度数值和焦点可见性。
