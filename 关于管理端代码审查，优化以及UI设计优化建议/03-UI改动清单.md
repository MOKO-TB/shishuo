## 二、`AdminConsoleView.tsx` —— Hero 只在概览页渲染

### 改了什么

把原本无条件渲染的 `<header className="admin-console-head">`（海报区）改成按当前标签页条件渲染：

```jsx
{tab === 'overview' ? (
  <header className="admin-console-head">
    {/* 原样保留：面包屑 + 大标题 + 说明 + 右侧状态卡 */}
  </header>
) : (
  <header className="admin-compact-head">
    <div className="admin-compact-title">
      <span className="admin-compact-crumb">管理端 /</span>
      <h2>{activeTabLabel}</h2>
    </div>
    <div className="admin-compact-meta">
      <span className="admin-compact-stat">revision {health?.workspaceRevision ?? '—'}</span>
      <span className="admin-compact-stat">{stats.users} 个账号</span>
      <button className="button button-ghost admin-refresh" onClick={() => void loadOverview()} disabled={loading}>
        <RefreshCw size={14} className={loading ? 'spin-icon' : undefined} />
        刷新
      </button>
    </div>
  </header>
)}
```

同时新增一行取当前页名：

```jsx
const activeTabLabel = TABS.find((item) => item.key === tab)?.label ?? '概览'
```

### 为什么

原实现中海报区（面包屑 + 48px 大标题 + 说明 + 状态卡）写在所有 9 个标签页的公共位置，实测占掉 **390px**。1440×900 下留给列表的高度只剩 510px。

### 实测效果

| | 改前 | 改后 |
|---|---|---|
| 账号管理 Hero 是否渲染 | 是 | **否** |
| 内容区起点 | y = 390 | **y = 216** |
| 内容区可用高度 | 517 px | **684 px（+32.3%）** |
| 首屏可见账号 | 7 / 9（第 8 个被切） | 8 / 8（本地只有 8 个，全可见） |

## 三、`admin-console.css` —— 四处改动

### 3.1 新增紧凑页头样式（+56 行）

```css
/* 功能页紧凑页头：海报式 Hero 只属于概览页，其余页面把纵向空间还给列表。 */
.admin-compact-head {
  position: sticky;
  top: 0;
  z-index: 6;
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 16px;
  min-height: 56px;
  margin: 0 0 14px;
  padding: 0 2px;
  background: var(--paper);
  border-bottom: 1px solid var(--line);
}

.admin-compact-title {
  display: flex;
  align-items: baseline;
  gap: 9px;
  min-width: 0;
}

.admin-compact-crumb {
  font-size: 11px;
  letter-spacing: 0.05em;
  color: var(--faint);
  white-space: nowrap;
}

.admin-compact-title h2 {
  margin: 0;
  font-family: var(--serif);
  font-size: 17px;
  font-weight: 600;
  color: var(--ink);
  white-space: nowrap;
}

.admin-compact-meta {
  display: flex;
  align-items: center;
  gap: 10px;
  flex: none;
}

.admin-compact-stat {
  font-size: 11px;
  color: var(--muted);
  padding-right: 10px;
  border-right: 1px solid var(--line);
  font-variant-numeric: tabular-nums;
  white-space: nowrap;
}
```

**要点**：`position: sticky; top: 0` 让页头在滚动时贴住内容区顶部，切换模块时标题始终可见。若外层有固定顶栏，把 `top` 调到顶栏高度。

### 3.2 暗色主题根因修复（2 处）

**改前**

```css
.admin-standalone {
  min-height: 100vh;
  background: var(--cream);
}

.admin-standalone-bar {
  background: rgba(251, 249, 243, 0.9);
  backdrop-filter: blur(14px);
}
```

**改后**

```css
.admin-standalone {
  min-height: 100vh;
  /* 原为 var(--cream)：该令牌在暗色主题里仍是浅米色 #f2ede1，
     导致暗色下外层是浅底、文字却是近白色 --ink，对比度只有 1.04:1。
     页面底色应跟随 --paper，才能与文字令牌同步翻转。 */
  background: var(--paper);
}

.admin-standalone-bar {
  background: color-mix(in srgb, var(--surface) 90%, transparent);
  backdrop-filter: blur(14px);
}
```

**根因说明（重要）**：这不是"硬编码色值"，而是 `[data-theme='dark']` 里 `--cream` 被设成了 `#f2ede1`（和亮色几乎同值），而容器正好用它。

```css
[data-theme='dark'] {
  /* ...其他令牌都正确翻转了... */
  --cream: #f2ede1;   /* ← 唯独这个没跟着变深 */
}
```

**为什么不能直接改 `--cream`**：`about.css` 里有 8 处 `color: var(--cream)`，是把它当"深色背景上的浅色文字"用的，改成深色会让那些文字消失。所以只能让管理端容器改用语义正确的 `--paper`。

**实测**：

| | 改前 | 改后 |
|---|---|---|
| 容器背景 | `rgb(242, 237, 225)` | `rgb(15, 23, 20)` |
| 标题文字 | `rgb(236, 243, 238)` | `rgb(236, 243, 238)` |
| **对比度** | **1.04:1** | **7.5:1** |

### 3.3 字号提升（5 处）

```css
.admin-stat-card > span        { font-size: 9px  → 11px }
.admin-login-foot              { font-size: 8.5px → 11.5px; color: var(--faint) → var(--muted) }
.admin-standalone-brand em     { font-size: 8px  → 10px }
.admin-standalone-user > em    { font-size: 8.5px → 11px }
.admin-standalone-home         { font-size: 9px  → 11px }
```

**为什么**：统计卡的标签（"账号""FAQ 总数""待处理问答"）是 9px，而数字是 24px；用户看得清"217"，看不清它代表什么。中文 9px 在 Windows 上笔画会粘连。

`--faint` 在纸色底上对比度只有 2.31:1，不达 WCAG AA 的 4.5:1，所以登录页说明同时换了颜色。

### 3.4 顶栏底色

`.admin-standalone-bar` 原本是 `rgba(251, 249, 243, 0.9)`（写死的浅色）。改用 `color-mix(in srgb, var(--surface) 90%, transparent)` 后自动跟随主题。

## 四、`StudentView.tsx` —— 提问默认匿名

```diff
- const [anonymous, setAnonymous] = useState(false)
+ // 默认匿名：同班同学只看到「一位同学」，实名需要学生主动选择
+ const [anonymous, setAnonymous] = useState(true)
```

### 为什么

这是隐私修复的 UI 侧一半。服务端投影层已经改成"他人的问答一律脱敏"，但学生自己发问时默认实名，会让 UI 上出现"我明明是实名的，为什么别人看到匿名"的困惑。默认改成匿名后，实名变成一个需要主动选择的动作。

### 配合的服务端改动

`server/permissions.mjs` 里把 `thread.student?.id === user.id || !isAnonymousThread(thread) ? thread : redactThread(thread)` 改成 `thread.student?.id === user.id ? thread : redactThread(thread)` —— 只改前端不服务端，别人看到的仍是真名。
