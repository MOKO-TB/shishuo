# 管理台改版原型

单文件、零依赖，直接用浏览器打开：`admin-redesign.html`

## 怎么用

右上角（手机上在底部）有一条**原型控制条**：

| 控件 | 作用 |
|---|---|
| **改版前 / 改版后** | 切换两套实现，同一份数据、同一套配色，只改布局与令牌落地方式 |
| **☾ 暗色** | 切换主题。**在「改版前」下切暗色可以看到 bug 复现** |
| **内容区 / 首屏可见** | 实时指标，随窗口大小和当前页面自动计算 |

页面底部四个标签可点：概览、账号管理、操作审计、内容核实。

## 能验证的几件事

### 1. Hero 是否该常驻（对应报告 P0-1）

切到「账号管理」，对比控制条上的数字：

| | 内容区高度 | 首屏可见账号 |
|---|---|---|
| 改版前 | 489 px | **7 / 9** |
| 改版后 | 701 px | **9 / 9** |

再切到「操作审计」：

| | 内容区高度 | 首屏可见记录 |
|---|---|---|
| 改版前 | 485 px | **4 / 17** |
| 改版后 | 705 px | **14 / 17** |

差距的来源只有一个：改版后 Hero 只在概览页渲染，功能页换成 56px 的紧凑页头。

### 2. 暗色主题到底坏在哪（对应报告 P0-2）

保持「改版前」，点一下「☾ 暗色」。会看到：

- 顶栏和外层背景仍是米纸色 `#f2ede1`
- 主标题变成近白色 `#ecf3ee`
- 结果是**白字压米色底**，标题几乎完全消失
- 但卡片、标签栏是深色的 —— 页面被劈成两半

点回「改版后」，深色完整生效：背景、卡片、文字三层一致。

### 3. 卡片流 vs 紧凑表格（对应报告 P1-2）

「操作审计」在两种模式下是两种完全不同的信息密度：

- 改版前：每条 76px 的卡片，三行才说完一件事，没有列头，眼睛无法纵向对比
- 改版后：44px 行高的表格，六列对齐，粘性表头，扫视路径是一条竖线

### 4. 主按钮不该每行一个（对应报告 P1-1）

「内容核实」：

- 改版前：每行右侧一个实心绿「标记已核实」，一屏 4 个同权重主按钮，等于没有主按钮
- 改版后：行内是描边小按钮；勾选后从上方浮出批量条，主操作在那里。整个页面任何时刻只有一个实心主按钮

勾两条试试，批量条会带着「已选 2 条」出现。

## 顺带做进原型的小项

- **字号阶梯**：全站最小 11px。改版前的统计卡标签是 8.5px，切到改版后能直接看出差别
- **焦点可见**：按 `Tab` 键，所有按钮、输入框、可点击行都有玉绿色焦点环。改版前没有
- **加载反馈**：点页头的「刷新」，按钮会禁用并转圈 1.2 秒。改版前点了毫无反应
- **按钮三档**：主（实心）／次（描边）／危险（红描边），「重置密码」用 danger 而不是主色
- **数字等宽**：`font-variant-numeric: tabular-nums`，时间、revision 纵向对齐不抖
- **跳转链接**：`Tab` 第一下会出现「跳到主要内容」，可跳过 4 个标签
- **移动端**：390px 下标签栏有右侧渐隐遮罩，提示还能横向滑

## 边界说明

- 这是**视觉与交互原型**，数据是写死的演示数据，没有接后端。
- 所有颜色、圆角、阴影都取自线上既有的设计令牌（`--paper` `--jade` `--ink` 等），没有引入新的品牌色。改版不是重做视觉，是把已有的一套令牌正确落地。
- 字体用系统栈兜底（Windows 下中文标题回落到宋体），线上用的是 `Noto Serif SC`，观感会更接近原设计。
- 落地到 `src/views/admin/` 时，改动集中在：
  - `AdminConsoleView.tsx`：Hero 与紧凑页头的条件渲染
  - 各 Panel 的列表容器：卡片流 → `<table class="tbl">`
  - `styles/admin*`：字号阶梯、`:focus-visible`、`.admin-standalone` 的 `background: var(--paper)`
