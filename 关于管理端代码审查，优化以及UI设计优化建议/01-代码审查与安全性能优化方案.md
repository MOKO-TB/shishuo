**审查对象**：http://121.37.30.147/admin/
**审查方式**：黑盒审查（无源码，通过接口行为、前端 bundle、响应头、并发压测推断）
**审查时间**：2026-11-18
**账号**：管理员 / 教师（陈砚，非 admin）/ 学生（林晓）

### P0-1 全站明文 HTTP，管理员密码裸奔

**证据**
```
POST http://121.37.30.147/api/auth/login   ← 明文
Set-Cookie: shishuo_session=...; Path=/; HttpOnly; SameSite=Lax; Max-Age=604800
                                        ↑ 无 Secure 标记
```
无 HSTS 头，无 80→443 跳转。

**影响**：校园网/公共 WiFi 下，任何同网段设备抓到一次请求即可拿到管理员会话；管理员后台 7 天内可被完全接管。这是本次审查**危害最大**的问题——其余所有权限校验都会因为会话被劫持而失效。

**方案**
1. 申请证书（域名 + Let's Encrypt 免费，或校园统一证书），Nginx 配置：
```nginx
server {
    listen 80;
    server_name your.domain;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your.domain;

    ssl_certificate     /etc/letsencrypt/live/your.domain/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your.domain/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_session_cache   shared:SSL:10m;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'" always;
    add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;

    location / { proxy_pass http://127.0.0.1:3000; ... }
}
```
2. 服务端设置 cookie 时加 `Secure`：
```js
res.setHeader('Set-Cookie',
  `shishuo_session=${token}; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=604800`
);
```
3. 后台管理加 `session 绝对超时`（如 12 小时）而非固定 7 天；管理员操作前可加二次验证（口令或 TOTP）。
4. 若短期拿不到证书（纯 IP 访问），至少：限制 `/admin/` 仅校内 IP 段、缩短会话到 8 小时、把 session 存 `sessionStorage` 之外不落地的方案（治标不治本，必须上 HTTPS）。

### P0-2 演示账号密码硬编码在前端 bundle，且是生产活跃账号

**证据**（`/assets/main-_SNOmmOJ.js` 明文可读）
```js
var el = { email: `student@shishuo.local`, password: `student123` }
var tl = { email: `teacher@shishuo.local`, password: `teacher123` }
```
两个账号实测登录成功，`status=active`。`/api/health` 还返回 `"demoAccounts":true` 主动提示存在演示账号。

**影响**：任何人打开 F12 就能以教师身份进入，看到学生真实提问、回复、沉淀 FAQ。竞赛演示阶段这是"评委体验入口"，但一旦真实上课使用，等于把教师账号公开。

**方案**（三选一，按上线节奏）
1. **演示环境与生产环境物理分离**：演示用独立实例（子域名 `demo.`），生产关掉演示账号；bundle 里的密码只用于 demo 域。

3. **最少改**：演示账号密码改为服务端启动时随机生成并写入日志（不落 bundle），前端"一键体验"按钮走后端 `POST /api/auth/demo-ticket` 下发短时会话（5 分钟、只读）。

配套：`/api/health` 去掉 `demoAccounts`、`aiConfigured`、`workspaceRevision` 等部署细节，只保留 `{"ok":true}`。

### P1-2 `/api/state` 默认实名暴露 + 可见范围过宽（学生能看到同学的实名提问）

**证据**：学生 `lin-xiao` 登录后 GET `/api/state`，返回 16 条 thread，其中 7 条属于他人，且**实名 + 正文 + 引导话术**全部下发：

```json
{"id":"t-spfa","courseId":"ds",
 "student":{"id":"song-jia","name":"宋嘉","anonymous":false},
 "question":"SPFA 判负环的原理是什么？为什么入队次数超过 n−1 就说明有负环？",
 "escalation":{"title":"SPFA 判负环的数学原理",
               "note":"作业最后一题要用，网上说法看不太懂。","urgency":"today"}}
```

**源码根因（已复核，三个因素叠加）**

| 因素 | 位置 | 事实 |
|---|---|---|
| ① 只对匿名脱敏 | `server/permissions.mjs:733-743` | `.map(thread => mine \|\| !isAnonymousThread(thread) ? thread : redactThread(thread))`——**非匿名 thread 原样下发，含 `student.id` / `name`** |
| ② 前端默认实名 | `src/views/StudentView.tsx:188` | `useState(false)`——提问框默认「实名提问」，需手动点才匿名 |
| ③ 学生可见全部课程 | `server/policy.mjs:66-68` | `studentCourseTeacherMap` 无条件 `map = PILOT_COURSES` 全集 + `CAMPUS_COURSE_ID`，**不按选课分配** |

三者相乘的结果：**任意学生登录后，默认能看到 5 门试点课 + 校园域下所有"待答"问题的同学实名、原题、作业紧迫度**。这不是过滤漏了一处，是三个设计决策叠加出来的默认态。

**影响**：提问措辞、作业进度、焦虑程度（`urgency: "today"`）都属于个人信息。教育场景下《个人信息保护法》最小必要原则要求"仅收集/展示达成目的所必需的信息"——"同问"功能只需要知道"有人问了同类问题"，**不需要知道是谁**。

**方案（按性价比排序）**

1. **默认匿名（改一行，收益最大）**
   `StudentView.tsx:188` 改 `useState(true)`，把"实名"变成需要主动选择的动作。同时把开关文案改成可感知后果的表述：「匿名（同学只看到"一位同学"）」/「实名（同班同学可见你的姓名）」。

2. **"同问"场景不必带身份**
   即使实名提问，对**非本人的待答同问**也应只下发 `{ id, courseId, question, status, createdAt }` + 匿名学生对象。实名信息只在两处需要：教师端（教学必需）、管理员端（治理必需）。
   ```js
   // permissions.mjs projectWorkspace 学生分支
   function projectThreadForPeer(t) {
     return {
       id: t.id, courseId: t.courseId, question: t.question,
       status: t.status, createdAt: t.createdAt, clusterId: t.clusterId,
       student: { id: `anon-thread-${t.id}`, name: '一位同学', anonymous: true },
     };
   }
   ```

3. **收紧学生课程范围**
   `studentCourseTeacherMap` 改成读 `users.courses_json`（与教师同一套分配机制），未分配时只给 `profile.defaultCourseId`。当前"人人可见 5 门课"会让一个只学高数的学生也看到数据结构课的提问。

4. **`escalation.note` 单独处理**
   这个字段是学生写给老师的私密说明（"作业最后一题要用"），对同班同学没有存在必要，投影时直接剔除。

### P1-3 AI 网关 `baseUrl` 可任意修改 → Key 外泄 + SSRF

**证据**
```json
GET /api/admin/ai-settings
{"settings":{"configured":true,"enabled":true,
 "baseUrl":"https://sub.qixiangai.com.cn/v1","model":"deepseek-flash",
 "apiKeyMasked":"sk-…8bd6","source":"database"}}
```
`POST /api/admin/ai-settings` 可保存 Key / Base URL / 模型 / 额度（接口文档自述）。

**风险**
1. 管理员会话被劫持后（P0-1），攻击者可把 `baseUrl` 指向自己的服务器，下一次调用即拿到完整 API Key。
2. 若服务端不校验协议与主机，`baseUrl` 可填 `http://127.0.0.1:6379`、`http://169.254.169.254/latest/meta-data/`（云主机元数据）→ SSRF 读内网/云凭证。

**方案**
1. `baseUrl` 白名单：只允许 `https://` + 预置域名数组（`sub.qixiangai.com.cn`、`api.deepseek.com`），保存时校验，不匹配直接 400。
2. 出站请求禁解析到内网：DNS 解析后校验 IP 不在 `10/8`、`172.16/12`、`192.168/16`、`127/8`、`169.254/16`、`::1`、`fc00::/7`。
3. Key 用 `AES-256-GCM` 加密存库（密钥走环境变量），而非明文入库；日志中禁止打印 Key 明文（当前掩码 `sk-…8bd6` 暴露后 4 位，可接受但建议只显示 `sk-…`）。
4. 保存 AI 配置时二次确认 + 记审计（当前 audit 有 `ai-settings` 动作类型则更好）。
5. 调用超时/重试上限：`timeout: 20s`, `retry: 1`，失败降级为"AI 暂不可用，已转教师"（避免 AI 挂了整站白屏）。

## 三、性能问题

### P0-4 出口带宽约 2.5 Mbps，首屏 2.1 MB 未压缩

**实测**
| 资源 | 大小 | 单请求 | 10 并发 |
|---|---|---|---|
| `main-_SNOmmOJ.js` | 807 KB | 133 ms | **25.5 s** |
| `styles-Cfi8CuD1.js` | 692 KB | 1.14 s | — |
| `styles-fq0sMNF1.css` | 555 KB | 111 ms | — |
| `admin-DoT9iokV.js` | 80 KB | **2.2 s** | — |
| 合计首屏 | **2.11 MB** | | |

80 KB 文件要 2.2 秒 → 有效带宽约 300 Kbps～2.5 Mbps（视并发）。10 个用户同时进站即排队到 25 秒。

**方案（按性价比排序）**
1. **开 gzip/brotli（5 分钟，收益最大）**：2.11 MB → 约 600 KB（-70%）：
```nginx
gzip on;
gzip_comp_level 5;
gzip_min_length 1024;
gzip_types text/css application/javascript application/json image/svg+xml;
gzip_vary on;
brotli on;                       # 若装了 ngx_brotli，优先 br
brotli_comp_level 5;
brotli_types text/css application/javascript application/json image/svg+xml;
```
2. **HTTP/2**：`listen 443 ssl http2;`（需先上 HTTPS）。HTTP/1.1 下 4 个资源只能 6 连接并发，队头阻塞明显。
3. **静态资源上 CDN 或对象存储**（OSS/COS + CDN 免费额度即可）。静态文件不该由应用服务器出带宽——这是当前最致命的瓶颈，换 CDN 后带宽问题直接消失。
4. **代码分割**：当前 `styles-Cfi8CuD1.js`（692 KB）是 vendor chunk，主站和 admin 共用全量。改为路由级 `React.lazy` + `manualChunks`，admin 分包单独加载；首屏只需主站 chunk。
5. **CSS 555 KB 偏大**：检查是否打包了整个 Tailwind 全量（未 purge）或含 katex 全量字体。用 Tailwind 的 `content` 配置 + 只引需要的 katex 样式，可降到 60–80 KB。
6. **字体子集化**：若有中文字体文件，用 `fonttools pyftsubset` 只保留常用 3500 字，体积可降 80%。

### P0-5 `/api/state` 并发雪崩

**实测**
```
单并发:   p50 174ms  (155 KB)
20 并发:  p50 6.1s   p95 20.7s   max 34s   2/60 失败
对照 /api/state/revision 20 并发: 37ms   ← 说明 DB 连接不是瓶颈
```
revision 接口只读一行，20 并发仍 37ms；state 接口 20 并发就 6 秒 → **瓶颈在单请求内部**：全量 JSON 读取 + 深度权限过滤 + 重新序列化，全部跑在 Node 单线程，阻塞事件循环。

**方案**
1. **加缓存（最快见效）**：
```js
// revision 不变就不重算；key 带 viewer 角色，避免越权串数据
const cacheKey = `state:v${revision}:${role}:${courseIds.join(',')}`;
let cached = await redis.get(cacheKey);
if (!cached) {
  cached = JSON.stringify(buildStateFor(viewer));
  await redis.set(cacheKey, cached, 'EX', 300);
}
```
配合写操作时 `incr revision` 天然失效。预期 p95 从 20 s 降到 50 ms 以内。
2. **字段裁剪 + 分页**（同 P1-2）：155 KB 里 153 条 FAQ 占大头，FAQ 不该塞进个人 state。拆成 `/api/faqs?courseId&page`，单页 20 条，首屏 payload 从 155 KB 降到 15 KB 量级。
3. **增量同步替代全量快照**：已有 `revision` 机制，加 `GET /api/state?since=11` 只返回变更条目（后端存 revision→delta 的 change log）。
4. **不要同步序列化大对象**：`JSON.stringify` 155 KB 在 Node 里约 1–3 ms，不是主因；主因是全量过滤时对每条 thread/faq 做深拷贝 + 权限判断。改为只对当前用户可见的条目做投影（先 filter 再 map，别先 map 再 filter）。
5. **进程模型**：确认是单进程还是 cluster。若是 `node app.js` 单进程，加 `pm2 start app.js -i max` 或按 CPU 核数起 cluster，单核阻塞才不会拖死全站。
6. **数据库层**：**已复核确认**——工作区以单个 JSON 文档整行存在 `workspaces` 表（README 第 3 节亦自述"以一个 JSON 文档整体保存"），读一次要解析整行 155 KB。长期应拆表（threads / faqs / notifications 独立表 + 索引 + 分页查询），JSON 列只做快照备份。仓库已有 `workspace_entities` 镜像表（问答 / FAQ / 通知按行落库），可作为拆表的现成基础。

### P1-4 全量快照写入 → 并发编辑互相覆盖

**证据**（`main.js`）
```js
await B(`/api/state`, { data: r, baseRevision: n.revision })
// 冲突时：_"共享空间已有更新，已载入最新版本"_  ← 直接丢弃本地修改
```
两位教师同时编辑 → 后保存者被静默覆盖，且**本地修改直接丢失**（无 diff、无提示保留）。

**方案**
1. 短期：冲突时前端弹出"你的修改与 X 老师的改动冲突"，提供"覆盖/放弃/查看差异"三选项，而不是静默丢弃。
2. 中期：把前端写入路径切到已落地的动作接口（`/api/threads/*`、`/api/faqs/*`、`/api/notifications/read`），每个操作只提交自己那一条，冲突面从"整站"缩到"单条"，再淘汰整包 PUT（排期第 11 项）。
3. 长期：字段级 `updatedAt` + 服务端合并（last-write-wins per field）。

### P2 级性能项

| 编号 | 问题 | 方案 |
|---|---|---|
| P2-9 | 图片走 base64 JSON 上传（+33% 体积，Node 内存峰值 11 MB/次） | 改 `multipart/form-data` 直传；或前端压缩到长边 1600px、≤500 KB 再传 |
| P2-10 | 无图片缩略图 | 服务端用 `sharp` 生成 320px 缩略图，列表页只加载缩略图 |
| P2-11 | 接口无 `offset/cursor` 分页 | `audit?limit=200`、`users` 全量返回；>1000 条时必崩，加 `?cursor=&limit=` |
| P2-12 | 无 ETag / 304 | `/api/state`、FAQ 列表加 `ETag: W/"rev12"`，未变更返回 304 |
| P2-13 | 静态资源无 `br` 预压缩 | 构建时生成 `.br`/`.gz`，Nginx `gzip_static on; brotli_static on;` |

## 四、功能与工程完善建议

1. **审计日志补全**：当前只记录 17 条管理动作。需覆盖：登录成功/失败、越权 403、state 写入、AI 配置变更、密码重置、封禁。字段加 `ip`、`userAgent`。
2. **数据备份**：共享工作区是"单份 JSON 全量覆盖"，一次误操作即全站内容归零。加每日快照（定时 `GET /api/state` 落 S3/本地）+ 保留 30 天，后台提供"回滚到某日"按钮。
3. **内容审核闭环**：审核队列、敏感词、图片审核都已有，但缺少"审核命中率/误杀率"统计。`/api/admin/moderation/overview` 只有 187 字节，建议补 `今日拦截数 / 人工复核数 / 误判数`。
4. **教师端权限说明**：前端文案"陈砚（管理员）"与实际不符，容易在答辩现场被评委问到"为什么这个账号进不了管理台"。统一为"教师"或真的提权。
5. **错误监控**：无前端埋点/后端错误上报，线上 500 无人知晓。接 Sentry 免费版（前端 + Node，10 分钟接入）。
6. **健康检查分级**：`/api/health` 应区分 liveness（进程活着）和 readiness（DB/Redis 可用），否则负载均衡会把坏实例当好的。
7. **限流兜底**：除登录外，`/api/uploads/image`、`/api/state`、AI 调用都应有 per-user 配额（AI 已有 dailyLimit，好）。
8. **无障碍与移动端**：后台表格在手机上横向溢出（未实测，建议检查 `admin-users` 断点）。

## 五、修复优先级排期（按投入产出）

| 顺序 | 事项 | 工作量 | 收益 |
|---|---|---|---|
| 1 | Nginx 开 gzip + HTTP/2 | 10 分钟 | 首屏 2.1 MB → 600 KB，并发 25 s → 3 s |

| 4 | 上 HTTPS + Secure cookie | 2 小时 | 堵住 P0 会话劫持 |
| 5 | 提问默认匿名（`useState(true)`，1 行） | 5 分钟 | 立刻收敛 P1-2 隐私暴露面 |
| 6 | `/api/state` 加 Redis 缓存 | 2 小时 | p95 20 s → <50 ms |
| 7 | `/api/state` 字段裁剪 + 拆分 FAQ 接口 | 1 天 | 155 KB → 15 KB，同时修隐私 |
| 8 | 登录限流 | 半天 | 防爆破 |
| 9 | AI baseUrl 白名单 + Key 加密 | 半天 | 防 Key 外泄/SSRF |
| 10 | 数据快照备份 | 半天 | 防误操作归零 |
| 11 | 细粒度接口重构 | 3–5 天 | 根治覆盖冲突 |

> **⚠ 已删除原第 3 项「`PUT /api/state` 加角色校验」**：源码复核后确认学生**必须**能调用该接口——学生的提问、同问、追问、转交、反馈、已解决、撤下、收藏、补充，全部通过 `PUT /api/state` 整包同步下发（前端 `store.tsx` 的保存路径）。若按原方案加 `requireRole(['teacher','admin'])`，**学生会立刻无法提问**。真正的方向是把前端切换到已落地的 `/api/threads`、`/api/faqs` 动作接口，再淘汰整包 PUT（对应第 11 项）。

**如果只有 1 天**：做 1、2、3、4、5。这五项能让系统从"演示可用"跨到"敢给真实班级用"。（1–2 纯运维配置，3–4 各 1–2 小时，5 只改一行。）

## 附：做得好的地方（答辩可以讲）

- 服务端权限校验到位：`/api/admin/*` 对学生和教师一律 403，不是只在前端藏按钮。

- 上传安全：魔数校验（内容与类型不一致直接拒）、白名单（PNG/JPEG/WebP）、413 体积上限。

- 静态资源：`immutable` 长缓存 + 文件名 hash，缓存策略正确。
- 数据一致性：有 `revision` 乐观锁（虽然提示策略需改进，但机制是对的）。
- 风控骨架完整：敏感词库（8 类）、图片审核、内容审核队列、审计日志，成型度超过一般学生项目。
