# 实施补丁

这里是在 `_tmp/shishuo-opt` 副本中改好并实测通过的 6 个文件。目录结构与仓库一致，可直接覆盖对应路径。

## 文件清单

| 补丁文件 | 对应仓库路径 | 改动 |
|---|---|---|
| `server/index.mjs` | 同路径 | gzip 压缩、Permissions-Policy、条件 HSTS |
| `server/api.mjs` | 同路径 | `/api/state` 响应缓存、SSRF 拦截 |
| `server/permissions.mjs` | 同路径 | 他人问答强制脱敏 |
| `src/views/admin/AdminConsoleView.tsx` | 同路径 | Hero 只在概览页、功能页紧凑页头 |
| `src/views/StudentView.tsx` | 同路径 | 提问默认匿名 |
| `src/styles/admin-console.css` | 同路径 | 紧凑页头样式、暗色修复、字号 |

## 三种用法

**一、直接覆盖（最快）**

```bash
cp -r 实施补丁/. <仓库根目录>/
npm run build
```

**二、先看差异再决定（推荐）**

```bash
# 以 server/api.mjs 为例
diff -u <仓库>/server/api.mjs 实施补丁/server/api.mjs
# 或用 git
git diff --no-index <仓库>/server/api.mjs 实施补丁/server/api.mjs
```

**三、只读改动说明**

看 [03-UI改动清单](../03-UI改动清单.md) 与 [04-代码改动清单](../04-代码改动清单.md)，里面按文件列了改前/改后代码和理由，可手工照做。

## 应用后必须做

```bash
npm run build          # 前端改了 .tsx 和 .css，必须重新构建
# 重启服务
```

**只覆盖服务端文件不重启、或只覆盖前端不 build，都看不到效果。**

## 注意事项

1. **如果仓库在这之后又改过这 6 个文件**，不要直接覆盖——先 `git diff` 看是否冲突，两份改动都要保留时手工合并。
2. **`server/index.mjs` 的 gzip 与 Nginx 的 gzip 不要同时开**。前面有 Nginx 做压缩时，关掉 Node 这层，否则会压两遍。
3. **`server/permissions.mjs` 的脱敏改动会让同学提问显示为「匿名同学」**，这是预期行为，「同问」功能依赖的 `thread.id` 与 `clusterId` 都保留了。
4. **`AI_ALLOW_PRIVATE_BASE_URL=1`** 只用于本地联调 mock 上游，生产环境不要设。
