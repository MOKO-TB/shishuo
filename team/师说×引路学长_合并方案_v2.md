# 「师说」×「引路学长」合并方案（v2 · 基于服务器实测）

> v1 只看了 HTTP 接口就下判断，把「师说」的数据层误判成"单文件 JSON 存储"。本次登录服务器做了只读侦察，**推翻了几条结论**，以本文为准。
> 侦察方式：只读命令（`ls`/`cat README`/`systemctl cat`/`file`/`ss`），**未修改任何文件、未重启任何服务**。
> 日期：2026-11-18

---

## 〇、先纠正 v1 的三处误判

| v1 的说法 | 实测事实 | 影响 |
|---|---|---|
| 「数据层是 `/api/state` + revision 单文件 JSON，无事务」 | **SQLite（`node:sqlite`）+ WAL**，库在 `data/shishuo.db`；工作区是存在 `workspace_entities` 表里的一个 JSON 文档，`revision` 是乐观锁 | 数据层比想象中结实；备份要备份 `.db` + `-wal` + `-shm` 三个文件，不是抄一个 json |
| 「功能不缺，缺 AI 和护栏」 | 功能比"不缺"还要多：已有 **81 条试点 FAQ + 157 条检索评测用例 + 检索引擎 + 知识库视图 + 答疑洞察** | 合并的对象不是"功能"，而是"知识域" |
| 「部署用 nginx 反代 + 目录软链」 | **服务器没装 nginx**，Node（`server/index.mjs`）自己监听 80 直出；`systemd` 单元是 `shishuo.service`，`WorkingDirectory=/opt/shishuo` | 部署方案要按实际形态写，不能凭空加 nginx |

---

## 一、结论

| 问题 | 答案 |
|---|---|
| 能不能合并？ | **能，而且比 v1 判断的更值得做**——因为师说已经有"知识库 + 检索 + 评测"的完整架子，缺的恰好是引路学长手里的校园生活语料。 |
| 怎么合？ | **合数据，不合代码**：把引路学长的 73 条校园知识卡接进师说已有的 FAQ / 检索 / 评测三件套。 |
| 要不要两个服务一起跑？ | **暂不需要**。师说的知识库是内置数据 + 引擎，不是外挂 agent，加语料不需要第二个进程。 |
| 现在最急的是什么？ | 不是合并，是 **师说的 AI 根本没配通**（`.env` 里 `AI_API_KEY` 为空 → `/api/health` 报 `aiConfigured:false`）。填一个 key 比做一个月合并都有用。 |

## 三、关键发现：两边的知识域是互补的，不是重叠的

| | 师说现有 | 引路学长有 |
|---|---|---|
| 域 | **课程内容**（5 门试点课：章节、知识点、习题） | **校园生活**（考研升学、奖助学金、入党、社团、竞赛、办事流程、宿舍、校园卡、图书馆、校历） |
| 形态 | `pilotFaqs.ts` 81 条（章节/别名/标签）+ `pilotEval.ts` 157 条评测 | `knowledge.json` 73 条（可信度 A-D + `source_url`） |
| 检索 | `lib/engine.ts`：检索 / 置信度 / 别名 / 聚类 / 知识缺口 | 无检索层，靠模型调用 `search_knowledge` 工具 |
| 出处 | 课程内引用 | **带 `source_url` 与可信度分级** |

**这就是合并的全部理由**：师说的引擎、评测、知识库视图已经建好，跑的是"课程答疑"；引路学长攒了一整套"校园生活"语料但缺检索层和闭环流程。**把语料放进师说的引擎，两边都不需要重写。**

合成后的产品形态：**一个入口，两条知识域**——课上问"洛必达条件"，课下问"奖学金怎么申请""什么时候放假"。

## 四、三种合并方案对比

| | A · 服务并置 | **B · 知识域合并（推荐）** | C · 深度融合 |
|---|---|---|---|
| 做法 | 引路学长 Web 跑在 8081，两个网址各自为政 | 73 条知识卡 → 师说 FAQ + 评测集，走同一引擎 | 把引路学长的地图/绩点/图书馆重写成师说 React 页面 |
| 改动 | 服务器加一个 systemd 服务，师说零改动 | 改 `src/data/`、跑评测，不动 `server/` | 前端 + 后端都要动 |
| 工期 | 半天 | **2–3 天** | 2 个迭代 |
| 收益 | 快速多一个能用的入口 | **用户无感切换，一个入口两条域**；引用可溯源 | 体验最统一 |
| 风险 | 两套体验、两套数据、用户要记两个网址；1.7 GB 内存再扛一个 Python 进程 | 低（只加数据 + 评测） | 高（要动核心视图与权限投影） |
| 需要源码 | 不需要 | 需要（在服务器上，已有） | 需要 |

### 推荐：**先 B，暂不做 A 和 C**

- B 是唯一能让"合并"产生产品价值的做法，成本又最低。
- A 留作后路：如果后面确实需要"校园地图/绩点计算"这类工具能力（师说引擎做不了），再把引路学长 Web 作为第二个入口挂上。
- C 现在不值得做。

## 五、方案 B 实施步骤（文件级）

### 步骤 0 · 先给师说建版本控制（**必做，否则别改代码**）

`/opt/shishuo` 目前**不是 git 仓库**。改代码没有回滚能力，这是比"能不能合并"更急的问题。

```bash
cd /opt/shishuo
cat > .gitignore <<'EOF'
node_modules/
dist/
data/*.db
data/*.db-wal
data/*.db-shm
data/uploads/
.env
EOF
git init && git add -A && git commit -m "chore: 纳管现有线上版本（基线）"
```

> 或者把现有代码推到一个私有 GitHub 仓库，与本地开发同步。**没有这一步，任何合并都是在裸奔。**

### 步骤 1 · 数据映射（0.5 天）

引路学长知识卡 → 师说 FAQ 结构。字段对应：

| 引路学长 `kb/knowledge.json` | 师说 FAQ（`actions.mjs` 的 `upsertFaq`） | 说明 |
|---|---|---|
| `id`（如 `A001`） | `id` → 前缀改 `campus-A001` | 避免与试点课程 FAQ 撞号 |
| `title` | `question`（主标题） | 知识卡标题本身就是问题式表述 |
| `content` | `answer` | — |
| `category`（考研/奖助/…） | `tags` + 新增 `domain: "campus"` | 用于知识库视图分域 |
| `tags` | `tags` | 合并去重 |
| `credibility`（A/B/C/D） | 新增字段 `credibility` | 前端可显示"官方来源 / 学长亲测" |
| `source_url` | 新增字段 `source` | **满足「引用可溯源率 100%」** |
| `source_channel` | `source` 的补充说明 | — |

产出：一个一次性转换脚本（放 `dev/import-campus-kb.mjs`），把 JSON 转成 `campusFaqs.ts` 或直接 POST 到 `/api/faqs`。

> 两种落法：**构建时**写进 `src/data/campusFaqs.ts`（推荐，随代码走、可回滚、可 review）；**运行时**走 `/api/faqs` 动作 API（适合后续老师在后台增补）。

### 步骤 2 · 接入检索与知识库视图（1 天）

- `src/lib/engine.ts` 的检索入口加上 campus 域，别让"奖学金"被课程术语表误匹配。
- `src/views/KnowledgeView.tsx` 增加「校园生活」分区（按 `domain` 过滤）。
- `src/data/pilot.ts` 的 5 门课白名单不动——**校园域不进课程白名单**，避免污染课程权限模型。

### 步骤 3 · 扩评测集（0.5 天）

- 从 73 条知识卡里挑**高频 30 条**，写成 `src/data/pilotEval.ts` 同格式的评测用例，另建 `campusEval.ts`。
- 跑 `npm run eval:retrieval`，记录基线命中率；**不达标不回退就是自欺欺人**。
- 这一步直接服务于协作规范里定的验收指标：FAQ 命中率、引用可溯源率、拒答正确率。

### 步骤 4 · 上线（半天）

沿用 `dev/deploy/` 已有的 paramiko 脚本（ssh 执行 + base64 上传，凭据走环境变量），不做新轮子。

## 六、如果要走方案 A（服务并置），按实测环境这样配

### 6.1 不需要 nginx

Node 直接监听 80，引路学长自己就是 HTTP 服务，绑 0.0.0.0:8081 即可：

```ini
# /etc/systemd/system/yinlu-web.service
[Unit]
Description=引路学长 校园助手 Web 版
After=network-online.target

[Service]
Type=simple
User=yinlu
WorkingDirectory=/opt/yinlu/current
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/yinlu/current/.venv/bin/python web_main.py \
          --host 0.0.0.0 --port 8081 \
          --sessions-dir /var/lib/yinlu/web-sessions
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

只需在**华为云安全组**放行 `TCP 8081`。

> 我先前准备的 `nginx-campus.conf` **在本机不适用**（没装 nginx），保留在 `yinlu-deploy/` 仅作参考。`deploy.sh` 里的 `--host 127.0.0.1 --port 8480` 也要改成 `0.0.0.0 --port 8081`。

### 6.2 内存是硬约束

| 项 | 数值 |
|---|---|
| 总内存 | 1.7 GB |
| 当前可用 | ≈ 1.3 GB（Node 占 104 MB） |
| 引路学长空闲占用 | 预计 150–250 MB（Python + 一个会话） |
| 一次多工具问答峰值 | 更高 |

结论：**放得下，但没有余量**。建议先加 2 GB swap 再上：

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

| # | 风险 | 等级 | 说明与处置 |
