# 「师说」×「引路学长」合并可行性评估与部署方案

> 评估对象
> - A：**师说 · AI 双通道课后答疑** —— `http://121.37.30.147/`（Vite + React SPA + Node API）
> - B：**引路学长 · 校园助手** —— `github.com/MOKO-TB/yinlu-xuezhang`（Python agent 引擎 + Web 只读模式）
> 评估日期：2026-11-18　结论口径：能不能合、怎么合、合完怎么上线

## 一、结论先行

| 问题 | 结论 |
|---|---|
| **代码能不能合并成一个工程？** | **不能，也不该合。** 两者是两套完全不同的技术栈与运行模型，强行合并的代价远大于收益。 |
| **产品能不能合并成一个入口？** | **能，而且值得合。** 同机并置 + 知识库打通，就是一套完整的「校园 AI 助手」。 |
| **现在能直接部署吗？** | **还不能。** 缺 3 样东西：服务器 SSH 凭据、师说源码、公网 LLM 的 API Key。部署产物已备好（`D:\KFGJ\WorkBuddy\projects\yinlu-deploy\`）。 |

## 二、两个项目到底是什么

| 维度 | A · 师说 | B · 引路学长 |
|---|---|---|
| 形态 | Web 服务（公网 SaaS 形态） | Windows 桌面应用 + 附带的 Web 只读模式 |
| 前端 | Vite + React SPA，按路由分页 | **单文件 `index.html` 792 KB**（含 mermaid/katex/marked 全套 vendored JS） |
| 后端 | Node HTTP API，`/api/state` + `revision` 单文件状态存储 | Python `ThreadingHTTPServer` + **SSE 流式**，零框架 |
| 核心逻辑 | 问答业务：提问 → AI 首答 → 教师接管 → 采纳 | **agent 引擎**：工具调用循环 + 沙箱 + MCP + 子代理 + 技能 |
| 模型接入 | `/api/ai/chat/completions`（**当前 `aiConfigured:false`，未配通**） | OpenAI 兼容客户端；内置默认指向**校园内网** `10.223.24.16:8080`，可换任意公网端点 |
| 账号体系 | 完整（注册/登录/邮箱验证码/重置密码/admin 审计） | **无登录**（作者明确选择"校园网内完全开放"，靠 IP 限流） |
| 数据资产 | 用户、提问、FAQ、公告（运行时产生） | **`kb/` 2.8 MB 结构化语料**：73 条知识卡（A/B/C/D 证据等级 + `source_url`）、校历、图书馆离线馆藏、校园地图、公众号/小红书/B 站语料 |
| 对外暴露面 | 面向公网，有鉴权 | 13 个只读工具白名单（`search_knowledge`/`campus_calendar`/`gpa_calc`/`library_search`/`map_*` 等），写工具与文件读取**整组拒绝** |
| 部署形态 | 已在华为云运行 | 从未上云，当前只在校园内网跑（依赖内网模型） |

### 关键差异一句话

**师说解决「谁来答、答完怎么闭环」；引路学长解决「校园信息从哪来、怎么带出处地回答」。** 前者是业务流，后者是知识底座。它们不是替代关系，是上下游关系。

## 三、为什么不能做"代码合并"

| # | 障碍 | 说明 |
|---|---|---|
| 1 | **双栈双运行时** | 合进一个工程意味着 Python + Node 两套运行时、两套依赖、两套部署。4 人学生团队维护成本翻倍，收益接近零。 |
| 2 | **agent 能力在对外模式下已被削掉** | 引路学长的核心价值（读写文件、跑命令、MCP、子代理）在 Web 模式里被白名单**主动禁用**，只剩 13 个只读工具。为了"合并"而把这些能力开放给公网，等于自己开一个 RCE 面。 |
| 3 | **账号体系对不上** | 师说的教师接管、采纳、审计全部依赖登录态与角色；引路学长 Web 模式**设计上就没有登录**。要合并必须先重写它的鉴权，工作量 > 重做一个模块。 |
| 4 | **状态模型冲突** | 师说用 `state + revision` 单文件状态；引路学长用"每访客一个会话目录 + SSE"。两套会话/持久化语义无法共用。 |
| 5 | **前端无法融合** | 引路学长是 792 KB 单文件手写 HTML，师说是 Vite 构建产物。二者没有共享的组件层，物理上拼不到一起。 |

> 说人话：**把 B 塞进 A，等于为了用它的知识库，把整个 Python agent 引擎搬到云上养着。** 正确做法是把知识库"取出来"给 A 用，让 B 自己独立跑。

## 四、推荐的合并方式：三层递进

### 第 1 层 · 服务并置（1 天，立即可做）

```
                    ┌─ :80  ──> 师说（原样不动）
公网 121.37.30.147 ─┤
                    └─ :8081 ─> 引路学长 Web（Python，独立进程、独立数据）
```

- 一台服务器两个 systemd 服务，互不影响，**任一方崩溃不波及另一方**。
- 师说完全不动（零回归风险），引路学长补齐"校园信息问答"能力。
- 用户视角：一个网址答疑办事，另一个网址问校园生活，后续用导航互通。
- **产物已就绪**：`yinlu-deploy/`（打包脚本 + 部署脚本 + nginx 配置 + 验收清单）。

### 第 2 层 · 知识库打通（2–3 天，合并的真正价值）

把 `kb/` 从"引路学长的私有语料"变成"两个产品共用的知识底座"：

| 数据 | 规模 | 去向 |
|---|---|---|
| `kb/knowledge.json` | 73 条知识卡，带 `credibility`（A/B/C/D）+ `source_url` | → 师说 **FAQ 库种子**（质量问题走教师精答，事实问题直接命中） |
| `kb/school-gzasc.json` / `wx-gzasc.json` | 1 MB + 1.2 MB 校园语料 | → 师说 RAG 检索语料（后续 embedding） |
| `kb/school-calendar.json` | 校历 | → 师说「什么时候放假/四六级」类问题的确定性数据源 |
| `kb/library-gzasc.json` | 图书馆离线馆藏 | → 师说生活服务 FAQ |
| `kb/notices.json` | 通知公告 | → 师说公告模块 |

**为什么这层最值钱**：师说的首个迭代验收指标里写着「**引用可溯源率 100%**」。引路学长的知识卡天生带 `source_url` + 可信度分级，正好是师说最缺的那块拼图——不用从零攒语料。

### 第 3 层 · 深度融合（1–2 迭代，可选）

- 在师说前端加一个「校园导航」入口，指向 `/campus/` 或独立子域；
- 把引路学长的**校园地图 / 图书馆 / 绩点计算**重写成师说的 React 页面（需师说源码）；
- 统一账号：引路学长接入师说的登录态，实现"同一个学号，两个入口免登录"。

> 这层要动师说源码，工作量最大，**建议放到师说 Sprint 2 之后**，先别做。

### 已实测验证的事

| 验证项 | 结果 |
|---|---|
| Web 模式能否脱离 Windows 桌面跑 | ✅ 本机实跑成功：`web_main.py --host 127.0.0.1 --port 8599` 正常启动，首页 200（792 KB），`/bridge-web.js` 200 |
| Web 路径是否含 Windows 专属依赖 | ✅ 无。`web_server/web_ui/web_profile/llm/session/sandbox/config/kb/paths` 全部只 import 标准库 |

| 服务器端口 | ✅ 22 开放（可 SSH）、80 开放（师说在跑）、443 关闭 |
| 模型端点 | ⚠️ 内置默认是校园内网 `10.223.24.16:8080`，**云服务器不可达**，必须换公网 API |
| 前端路径耦合 | ⚠️ `bridge-web.js` 硬编码 `/api/` 与 `/api/events`，所以**不能用 `/campus/` 路径前缀**，必须独立端口 |

## 六、风险清单

| 风险 | 等级 | 应对 |
|---|---|---|
| 引路学长 Web 版**无登录**就上公网 | 高 | 现有每 IP 12 次/分 + 全局并发 3 + 每日 2000 次；若要更严，加 nginx Basic Auth 或只对校园网段开放 |
| 单机双服务抢内存 | 中 | 引路学长是单进程多线程，空闲约 100–200 MB；部署后 `free -h` 复核，必要时加 swap |
| 一次多工具问答 30–40 s | 中 | nginx 已设 300 s；前端流式可见；给用户加"正在查资料"提示 |
| 公网 API 成本不可控 | 中 | 每日 2000 次配额 + `web-usage.log` 留痕，每周看一次 |
| 知识库内容时效（校历/通知是 2026-10 的） | 中 | 导入师说后标注"采集日期"，过期条目由 PO 每迭代复核 |
| 校园内网数据放公网 | 中 | 只放公开信息（公众号/官网/小红书已发布内容），不放成绩、学号等个人数据 |
