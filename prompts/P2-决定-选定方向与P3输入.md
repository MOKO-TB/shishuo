# 定方向决议（P3 输入）

> 用法：跑 P3 时，把本文件全文贴给 Zcode，再贴 `P3-收敛方案.md`。
> 决议日期：2026-11-15

## 选定方向

**主方向：问话寻家**（P2 方向一，评分预演 84 分，决策矩阵 23 分第一）
**场景**：老人走失
**一句话**：路人街头遇到说不清话的老人，用手机问几句，三分钟内拿到结构化线索单；若家属登记过档案，直接给出联系人与住址线索。

## 关键决定：并入方向二的一段，不做方向二整个

**为什么不单独做"别等24小时"**：它的本质是一个 system prompt 加流程，评委一句"调个 API 也能做"就可能压掉原创分。作为独立方向不划算。

**但它的"家属报案建档"环节要并进来**，理由是它解决本方向最致命的问题——冷启动：

- 问话寻家依赖"家属预登记档案"才能匹配，否则路人问出线索也无处比对。评委一定会问："老人家属没登记过怎么办？"
- 答案就藏在方向二里：**家属报案的每一次，都是一次自然建档**。家属为了报警要准备近期照片、当日衣着、体貌、疾病、常去地点——这些正好就是路人这边要匹配的字段。
- 所以不是"先有档案才能用"，而是"家属越着急，档案越全"。

**边界**：只把"报案要素采集"做成建档案的入口，不做独立的报案助手产品、不做报警卡导出、不做 110 对接。入口只留一个动作。

## 三条硬边界（P3 排期时不许突破）

1. **主演示必须走"零档案"路径。** 先用一段没有预登记的老人方言录音，当场产出线索单。匹配命中是加分项，不能是主戏——因为匹配靠的是自造档案，评委看得出是演的；而"方言碎语→结构化线索单"是真本事，且不需要任何人注册。
2. **不做三个场景的拼盘。** 灾害、旧衣两个场景一律不碰，哪怕时间有余。
3. **不做真实公安系统对接、不做定位追踪、不采集人脸。** 合规风险高于收益。

## 必须准备好的三个答辩问题

| 评委会问 | 必须答得上来的话 |
|---|---|
| 路人为什么不直接打 110？ | 110 接线员会问，但不会用方言多轮追问、不会把碎片重组、也不会生成一张能转发的线索单；我们做的是接线前的 3 分钟，不是替代报警 |
| 家属没登记怎么办？ | 零档案也能用，出线索单交给民警；登记过的才走直接匹配 |
| AI 听错方言怎么办？ | 只输出线索单不给结论，每条线索标可信度；低置信自动降级为人工选项，不替用户判断身份 |

## 演示三幕（3 分钟）

- **第 1 幕（40 秒）**：队员 A 扮路人，队员 B 扮老人说方言。手机录一段"我以前在纺织厂……女儿叫小芳……"的碎语。屏幕上线索单逐条浮现：单位、亲属称呼、可能年代、区域词。**全程不出现任何档案、不注册。**
- **第 2 幕（60 秒）**：切到家属端，队员 C 花 1 分钟录入一份档案（照片、衣着、常去地点）。说明"这就是家属报案时顺手完成的事"。
- **第 3 幕（50 秒）**：回到路人端，同一段录音再跑一次，这次给出匹配排名与联系人线索。
- **收尾（30 秒）**：一句话——"我们不是在做寻人平台，是在抢走失后的前三个小时。"

## 已知风险（P3 要写进风险表）

- 方言识别（SenseVoice 粤语支持待核实）→ 降级：普通话+关键词手选
- 现场噪音导致转写失败 → 降级：预录音频兜底，现场仍跑真实链路
- 线索单被误解为"身份结论" → 文案必须写"线索，非结论"
- 100h 内两入口工作量 → 后端共用一张表，前端两页，不再扩功能

## 顺带要修的两处（P2 产出里的小问题）

1. 模型名（GLM-4-Flash / GLM-4V）按实际可用版本核对一遍，别在文档里写错版本。
2. 合成数据必须显式声明。凡是用自造数据演示的（方言录音、家属档案），产品文档里写一句"演示数据为合成数据，不涉及真实个人信息"——这是加分项，不是减分项。
