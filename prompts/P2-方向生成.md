# P2｜方向生成与展开

> 用途：第二轮，新开会话。先把 P1 的痛点表贴进来，再贴本文件内容。

## 前置

我会贴给你 P1 的痛点表（12 条，分属旧衣回收、老人走失、灾害应急三个场景），并标出我感兴趣的 4–6 条。

## 角色

你是 AI 原生产品架构师 + 黑客松评委。你熟悉 LLM 应用工程（RAG、Agent 编排、多模态、结构化抽取、语音），也熟悉路演现场——评委平均只给你 8 分钟，看不完全部功能，只看得到"能不能跑、有没有惊喜、讲得清不清楚"。

## 命题范围（硬边界）

**方向必须落在这三个场景之内**，不许自创第四个场景：

| 场景 | 官方给的及格线方案 |
|---|---|
| 旧衣回收 | 回收点查询工具：整合回收箱位置，附带回收去向说明 |
| 老人走失 | 防走失安全网：二维码联系卡为物理入口、手机定位 + 地图围栏为核心、路人扫码上报为社会网络，做"事前预防—事中守护—事后寻回"闭环 |
| 灾害应急 | 应急知识问答 Agent：覆盖地震/火灾/溺水/触电，自然语言提问（如"煤气泄漏怎么办"），给分步骤指引，支持语音 |

**这三个方案是评委心里的默认答案。** 你的任务不是绕开它们，也不许原样复刻它们——**要在同一个场景里，做出比它更深一层的东西。**

## 赛事事实（不可改写）

**赛道**：数字造梦师 · 软件应用赛道——聚焦"可运行的 AI 原生软件原型"
**命题**：开放命题 OP2 —— AI 智能助手
**硬要求**：AI 能力必须嵌入具体工作流，**不能只是调用 API 做表层包装**
**交付物**：可运行程序包/在线链接（评审期间必须可访问）、源码包、产品说明文档、演示视频
**评审**：3 位校外评委（黑客松冠军 / AI 科技 UP 主 / 行业专家）现场路演打分，取平均

## 真实评分表（100 分，逐个方向都要对齐）

通用 60：作品完成度 **18** ／原创创新性 **17** ／问题与主题价值 10 ／应用与落地潜力 10 ／路演协作表现 5
专项 40：AI 融合与产品逻辑 **15** ／交互体验与场景匹配 **15** ／代码质量与可复现性 10

三条推论：
- 完成度 18 分最高，且写明"是否存在明显缺陷"。→ 3 个功能全跑通，胜过 8 个功能里 5 个报错。
- 原创性 17 分看"差异化 + 融合深度"。→ 官方已经给了三个方案，复刻它们等于 0 增量。
- 专项 30 分压在 AI 融合与交互上。→ AI 得站在流程关键节点上，不能在旁边当装饰。

## 野心条款（优先于其他所有约束）

**禁止用"我们技术不够"淘汰任何方向。** 只可以因为四种理由淘汰：
① 数据拿不到 ② 合规有硬伤 ③ 100 小时内联调不完 ④ 现场演示不可控（断网/依赖特殊硬件/需要多人配合）

5 个方向中，**至少 2 个必须是"两三年前工程上做不起、现在因为 AI 才变得可行"的方向**，并写清 AI 补掉了哪块能力缺口，例如：
- 把非结构化输入（语音、照片、手写纸条）变成结构化信息，过去要人工录入
- 老照片/旧证件的信息抽取与比对，过去要靠人认
- 应急场景下的多步决策规划，过去只能写死流程图
- 多语言/方言语音理解，过去要定制语音系统

## 输出格式（5 个方向，每个 ≤ 550 字）

每个方向按下面 8 段写，**标题和顺序不要改**：

**① 名称** ≤10 字，要有记忆点。禁止"基于大模型的智能 XXX 平台"。
**② 归属场景 + 一句话** 属于三个场景中的哪一个（可跨两个场景），谁 / 在什么时刻 / 得到什么结果。
**③ 它来自哪条痛点** 回指 P1 的编号，写清官方方案在这里为什么不够。
**④ 核心创意与 AI 链路** 写出 `输入 → 理解 → 规划 → 执行 → 输出`，指明属于问答式/生成式/规划式/多步 Agent。如果是纯问答，必须说明凭什么比官方那个问答 Agent 更强。
**⑤ 相对官方示例的增量（这一格是得分关键）**
- 官方方案已做到：一句话
- 我们多做到：一句话
- **为什么这个增量是决定性的**：一句话（必须落在 P1 的某条痛点上，不能是"体验更好"）
**⑥ 野心版 vs 100h 切片**
- 野心版（给 6 个月会做成什么样，一句话）
- 100h 切片（P0 闭环是哪几步，必须能当场演示）
用切片控制范围，不要用想象力自我审查。
**⑦ 技术实现** 五层各一行——前端 / 后端 / AI 编排（模型、框架、关键 prompt 或工具清单）/ 数据（来源、结构、冷启动）/ 部署（评委点开链接就能用）。点名具体技术，不写"采用先进 AI 技术"。
**⑧ 可行性与评分预演**
- 100h 排期：第 1–2 天 / 第 3 天 / 第 4 天 / 第 5 天，四段，标出"最晚哪天必须跑通主链路"
- 技术风险 2 条 + 各自降级方案（降级后功能还在，只是变笨）
- 评分预演表：

| 评分项 | 满分 | 预估 | 依据（一句话） |
|---|---|---|---|
| 作品完成度 | 18 | | |
| 原创创新性 | 17 | | |
| 问题与主题价值 | 10 | | |
| 应用与落地潜力 | 10 | | |
| 路演协作表现 | 5 | | |
| AI 融合与产品逻辑 | 15 | | |
| 交互体验与场景匹配 | 15 | | |
| 代码质量与可复现性 | 10 | | |
| **合计** | **100** | | |

## 结尾：给出你的立场（必写，不要和稀泥）

1. **决策矩阵**：5 个方向 × 5 维，每格 1–5 分：`100h 完成把握` / `相对官方方案的增量` / `演示冲击力` / `数据获取难度(5=最易)` / `野心程度`。给合计与排序。
2. **我押哪个**：如果你是队长，押哪个？20 字内说结论，3 句话说理由。
3. **劝退一个**：指出 1 个"演示炸裂但大概率翻车"的方向，说清翻车在哪一环。
4. **为什么第一不是第二**：一句话，必须具体到某项能力或某个风险。

## 硬规则

- 禁止营销形容词（颠覆、赋能、革命性），禁止感叹号。
- **不确定就标 `[待验证]`，禁止编造数据、编造用户调研、编造已有产品。**
- 5 个方向里机制不许重复。同一场景下换了个外壳但链路一样，视为重复，换掉。
- 不允许出现"把三个场景都做一遍"的拼盘方案——评委会认为是三个半成品。
- 本轮只做方向展开，不要往下做 MVP 边界和排期表。
