# 与「引路学长」的差异化说明（改了什么、为什么改、原创性边界）

> 结论先行：**「知了」是与引路学长完全不同的新作品**——新产品定位、新技术栈、新代码库；继承的只有方法论、工程纪律与经验教训。本文件夹（`Desktop/广应科黑客松`）与其一切产物均不复制引路学长的任何代码或文档内容。

## 1. 为什么必须新建而不是改

大赛红线（执行方案原文）："**禁止使用往届作品、已上线项目、课程作业等进行二次修改提交**"，且"所有核心开发必须在 100 小时限时周期内完成"。

引路学长的事实状态（来自其交付文档）：
- 2026 年 9 月在本校 48 小时黑客松完成系统原型 → 属于"往届（其他赛事）作品"；
- 已迭代至 v0.9.0 交付版、正备战挑战杯校赛 → 属于"进行中的参赛项目"。

因此把它改一改交上来，既踩红线也有原创性核查风险。正确姿势是：**新命题、新产品、新代码**，引路学长只当"教练"，不当"底稿"。用户判断"还没出现在校赛里所以能改"是对团队归属而言的；落到比赛合规上，走"全新作品"路线反而更稳也更强。

## 2. 差异化对照表（这就是"要改的地方"）

| 维度 | 引路学长（旧） | 知了（新） | 为什么改 |
| --- | --- | --- | --- |
| 产品定位 | 通用校园助手（地图+图书馆+编程带教+问答，大而全） | 只做"答疑互助"一个场景，做深做透 | 评委看"问题真实价值"，单点纵深 > 功能清单 |
| 形态 | 本地桌面单机（pywebview，离线优先） | **Web 在线多端**（评审要求在线链接可访问、多用户协同） | 命题是"平台"，且交付物要求在线部署 |
| 技术栈 | Python + pywebview + SQLite 单机 | FastAPI + Vue3 + ChromaDB + 云部署 | 团队已有 FastAPI+Vue3 实战（shiwu-market），100 小时里最快最稳 |
| 检索方案 | 2-gram 词面为主，向量通道后加 | **向量语义为主 + 关键词兜底混合** | 回归测试实测：向量 Top-1 81.9% vs 词面 54.3%；语义改写题词面 0%——直接用数据选型 |
| 答疑模式 | 单向 AI 问答 | **AI + 教师双通道漏斗 + FAQ 自成长闭环** | 命题核心要求；也是引路学长没有的运营闭环 |
| 知识来源 | 静态离线知识库（757 条） | 种子库 + 老师答案动态回灌，越用越准 | "落地潜力"得分点；演示有故事 |
| 功能取舍 | 地图、图书馆、编程引路、18 工具 | 全部砍掉，只留答疑漏斗 | 100 小时只够把一件事做到"可演示、无 bug" |
| 交互 | 桌面 GUI 对话 | 提问框即首页；转老师一键；教师端待办式 | "交互体验与场景匹配"15 分专项 |

## 3. 从引路学长继承的"软件资产"（方法论，不含代码）

1. **检索评测方法论**：构建题集 → 四策略回归 → 用数字选检索方案（复用其 209 题回归的结论与做法，题集为知了重建）。
2. **不编造纪律**：无来源不说、如实降级——引路学长最大的差异化亮点，直接继承为产品原则（答辩时可讲成工程文化）。
3. **可信度分级**：来源 URL + 可信度标注的语料规范，知了的 FAQ 库沿用此规范。
4. **语料清洗经验**：PII 脱敏、口径对照的做法，用于赛前种子库整理。
5. **团队分工模式**：PM/算法/前端/数据测试四角色协作与验收口径。
