# 「知了」· 师生答疑互助平台 —— 产品方案

> Slogan：**AI 秒答 · 老师兜底 · 答案可溯源**
> 对应命题：软件应用赛道固定命题 ③ 师生答疑互助平台
> 一句话：把"课后问题无处问、老师时间有限、重复问题刷屏"变成"AI 即时答准的秒答，答不准的自动流转到老师手里，好答案沉淀成学校自己的 FAQ 知识库"。

## 1. 痛点（对应官方命题描述）

| # | 痛点 | 现状 |
| --- | --- | --- |
| 1 | 课后问题无处问 | 下课后找不到老师，问同学靠缘分，问通用 AI 不贴本校、爱编造 |
| 2 | 老师时间有限 | 同一个问题每学期被问几十遍，重复劳动；老师难以及时看到真正需要人的问题 |
| 3 | 知识不沉淀 | 答过的题没有留下来，明年新生把同样的问题再问一遍 |

## 2. 产品方案：三层答疑漏斗

```
 学生提问（自然语言）
        │
        ▼
 ┌─────────────────────────────────────────────┐
 │ 第 1 层 · AI 秒答通道                        │
 │ RAG 检索校园 FAQ/教务知识库 → 大模型生成       │
 │ 带引用来源 + 置信度的回答；                  │
 │ 置信度不足 → 如实说"不确定"，绝不编造          │
 └──────────────┬──────────────────────────────┘
        答不上 / 学生点"转老师"
                ▼
 ┌─────────────────────────────────────────────┐
 │ 第 2 层 · 教师兜底通道                        │
 │ 未答问题池 → 按课程/学院分派给老师/助教        │
 │ 老师回答一次 →（学生采纳后）自动沉淀进 FAQ     │
 │ 可选：同学互助抢答，采纳得积分                │
 └─────────────────────────────────────────────┘
                ▼
 ┌─────────────────────────────────────────────┐
 │ 第 3 层 · FAQ 自成长知识库                    │
 │ 高频问题自动聚类去重 → 热门榜                 │
 │ 新答案进库 → AI 通道下次直接秒答              │
 └─────────────────────────────────────────────┘
```

**核心闭环（评委 15 秒能看懂的那种）**：问题 → AI 先答 → 答不了流转老师 → 老师的答案回灌知识库 → 下一个人被 AI 秒答。AI 在这里不是噱头，是漏斗第一层，节省的是老师的时间。

## 3. MVP 功能清单（100 小时内做完的）

| 模块 | 必做（MVP） | 冲刺（有余力才做） |
| --- | --- | --- |
| 学生端 | 提问、流式回答、来源引用卡片、"没答准→转老师"按钮、我的提问 | 语音提问、匿名提问 |
| AI 通道 | RAG 检索（向量 + 关键词混合）、置信度门限、拒答话术 | 多轮追问澄清 |
| 教师端 | 登录、未答问题池、回答、一键入库 | 按课程分派、办公时间预约 |
| 知识库 | FAQ 管理、答案采纳入库、热门问题榜 | 语义聚类去重、周报 |
| 运营/演示 | 预置真实问答种子数据、管理后台、数据看板 | 积分互助体系 |

## 4. 与评分标准的对齐

| 评分项 | 知了的设计 |
| --- | --- |
| AI 融合与产品逻辑 (15) | 双通道漏斗 = 功能闭环自洽；置信度门限 + 拒答 = Agent 判断能力，不是套壳 |
| 交互体验与场景匹配 (15) | 提问框即首页；转老师一键完成；教师端像待办清单而不是后台系统 |
| 代码质量与可复现性 (10) | FastAPI + Vue3 标准分层；README 一条命令起服务；docker-compose |
| 原创创新性 (17) | 全新代码库；亮点=答案可溯源 + FAQ 自成长闭环 |
| 问题与主题价值 (10) | 命题原文背书；预置本校真实高频问题数据 |
| 落地潜力 (10) | 老师零学习成本（回答即建设）；可推广到学院/部门二级知识库 |

## 5. 技术架构

```
┌─────────────┐   ┌──────────────────────────────┐
│  Vue 3 前端  │──▶│  FastAPI 后端                 │
│  (PC+移动端) │   │  ├ /ask        提问与流式回答  │
└─────────────┘   │  ├ /questions  问题池/教师通道  │
                  │  ├ /faq        知识库管理      │
                  │  └ /auth        学生/教师角色   │
                  └───┬──────────┬───────────┬────┘
                      ▼          ▼           ▼
                ChromaDB     SQLite       LLM API
                (向量检索)   (业务数据)  (校园端点/DeepSeek/
                      ▲                   Qwen/Kimi)
                      │
              bge-small-zh-v1.5 向量模型（本地已备）
```

- **检索**：向量语义为主 + 关键词兜底的混合检索；引路学长项目的 209 题回归测试已证明向量通道显著优于纯词面（Top-1 81.9% vs 54.3%，语义改写题词面 0% vs 向量 65.9%）——这个结论直接沿用。
- **不编造纪律**：检索无命中或低置信 → 明确回复"暂无把握，已帮你转给老师"，并展示来源。
- **部署**：开发期局域网 + 云服务器/内网穿透双保险；开赛第 1 小时先部署空壳，保证"在线链接"从第 2 小时起就存在。

## 6. 数据计划（赛前准备，允许）

- 从**公开官方渠道**（学校官网通知、教务制度、学生手册等）收集 200–500 条问答对语料，标注来源 URL 与类别，做成 JSONL 种子库。
- 语料收集清洗属于赛前准备；**代码开发全部在 11/4 之后**。

## 7. 90 秒演示黄金路径（录视频 / 路演都用这条线）

1. 学生问"期末缓考怎么申请？"→ AI 3 秒作答，附教务处来源引用。
2. 学生追问"我现在大二下能修双学位吗？"→ 知识库没有 → AI 如实说没把握 → 一键转老师。
3. 切教师端：问题池里出现这条，老师作答 → 学生采纳 → 答案自动进 FAQ。
4. 回学生端再问同一个问题 → AI 直接秒答，来源显示"教师审核"。
5. 收尾：看板展示本周 AI 化解率、热门问题 Top5。
